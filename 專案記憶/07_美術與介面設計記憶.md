# 美術與介面設計記憶

最後更新：2026-05-29

本檔記錄 Project Hina 的視覺資產、介面設計方向、互動狀態與 UI 除錯入口。

## 作業位置

- 全域樣式：`src/index.css`
- Tailwind 設定：`tailwind.config.js`
- 品牌文字：`src/config/branding.js`
- App header：`src/components/AppHeader.jsx`
- 背景：`src/components/GalaxyBackground.jsx`、`src/components/WindParticles.jsx`
- 主畫面：`src/pages/PianoRoom.jsx`
- 控制面板：`src/components/ControlPanel.jsx`
- 曲庫：`src/components/ScoreLibrary.jsx`
- 轉檔器：`src/components/ScoreConverter.jsx`
- 譜面顯示：`src/components/SheetDisplay.jsx`
- 視覺資產：`src/assets/galaxy.jpg`、`public/images/galaxy.jpg.jpg`

## 設計方向

- 介面應以實際可操作工作台為第一畫面，不做純介紹型 landing page。
- 音樂工作流需要清楚的狀態密度：目前曲目、播放狀態、音色、BPM、匯入結果、雲端狀態都應容易掃描。
- 控制元件要穩定，不因標籤長度、hover 或 loading 造成跳動。
- 卡片只用於重複項目、工具面板或 modal；避免卡片再包卡片。
- 按鈕與工具操作優先使用 lucide icon 搭配 tooltip 或短標籤。

## 主要畫面責任

- `PianoRoom`：第一屏入口，需讓使用者直接選曲、播放或進入鍵盤，不以介紹文案佔滿畫面。
- `PerformanceWorkspace`：播放與時間軸檢查，資訊密度可高，但控制列不能擠壓譜面。
- `PianoKeys`：琴鍵尺寸、active 狀態、note trail 與行動裝置觸控區要穩定。
- `ScoreConverter`：拖放、檔案清單、轉檔狀態、上傳狀態需在同一流程中可掃描。
- `ScoreLibrary`：列表、錯誤、空狀態、刪除確認需清楚，但不要取代主要編輯流程。

## UI 品質檢查

- 手機與桌面都要檢查文字不溢出、不重疊。
- 譜面、琴鍵、工具列需有穩定尺寸或 responsive constraints。
- loading、empty、error、disabled、busy 狀態都需有明確樣式。
- 背景圖片不可遮蔽主要文字；若亮度干擾，應調整 overlay 或局部背景，而不是犧牲可讀性。
- 色彩需避免整頁只有單一色相；保留音樂/星空氣氛但不能讓工具辨識度下降。
- 圖示按鈕需保留可理解的 title/aria-label；只有常見命令可單獨使用 icon。
- 長曲名、長檔名、錯誤訊息必須有換行或截斷策略，不能撐破控制面板。
- 譜面編輯區的播放時間軸是可拖曳 slider；段落按鈕只負責跳段，不再把整條時間軸當單純 click target。
- 新手教學文字必須對應目前實際可輸入格式；不要再使用未接線或會誤導的 `@grid` 範例。

## 資產規則

- 主要背景來源為 `src/assets/galaxy.jpg`；public 版本只供靜態路徑或部署兼容使用。
- 新增圖片時先確認 GitHub Pages base path 與 Firebase base path 都能載入。
- 若改為外部圖片，需有載入失敗 fallback，避免首屏空白或文字不可讀。

## 除錯入口

- 版面跑版：先檢查 `src/index.css` 與該 component 的 grid/flex constraints。
- 圖片不顯示：檢查 import path、public path、build base path。
- icon 缺失：檢查 `lucide-react` import。
- mobile 溢出：檢查固定寬度、長字串、button padding 與 grid columns。
- 中文亂碼或字體模糊：檢查檔案 UTF-8、字串 escape、text-shadow、過小字級與過低對比。
