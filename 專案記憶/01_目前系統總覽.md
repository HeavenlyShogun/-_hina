# Project Hina 目前系統總覽

最後更新：2026-05-29

Project Hina 是以 React + Vite 建立的風物之詩琴/樂譜工作台，核心能力包含樂譜編輯、播放預覽、MIDI/MusicXML 轉檔、雲端曲庫，以及 Firebase/GitHub 雙部署。

## 技術棧

- 前端：React 19、Vite 7、Tailwind CSS、Lucide React。
- 音訊：Web Audio API、`@tonejs/midi`、自製 `audioEngine` 與播放排程。
- 資料：JSON v2 樂譜、Slim JSON、MIDI、MusicXML/MXL。
- 雲端：Firebase Auth、Firestore、Firebase Hosting。
- 部署：GitHub Pages 與 Firebase Hosting 分開建置。

## 核心作業位置

- App 入口：`src/App.jsx`
- 前端入口：`src/main.jsx`
- 全域樣式：`src/index.css`
- 音訊引擎：`src/services/audioEngine.js`
- 播放控制：`src/services/playbackController.js`
- 樂譜狀態：`src/hooks/useScoreState.js`
- 播放 hook：`src/hooks/useScorePlayback.js`
- Firebase service：`src/services/firebase.js`
- Firebase 設定：`src/config/appConfig.js`
- 樂器定義：`src/constants/instruments.js`
- 譜面工具：`src/utils/score*.js`、`src/utils/midiToV2.js`、`src/utils/musicXmlToSlim.js`

## 系統資料流

1. 曲目來源從內建 slim-json、使用者文字譜、JSON、MIDI 或 MusicXML 進入。
2. `ScoreConverter`、`ScoreEditor` 或 `useScoreState` 將來源整理成可載入 payload。
3. `score.js` / `scoreDocument.js` 正規化為 editor 與播放共用的 canonical 結構。
4. `useScorePlayback` 依目前 tempo、playback config、audio config 建立播放計畫。
5. `playbackController` 負責 tick、tempo map、seek 與排程時間。
6. `audioEngine` 依 tone/instrument 載入 sample 或啟用合成 fallback 後發聲。
7. 儲存時由 `useCloudScores` / `firebase.js` 寫入 Firestore 的完整文件與摘要文件。

## 主要功能區

- `PianoRoom`：主畫面、特色曲目與工作區入口。
- `PerformanceWorkspace`：演奏/播放工作區。
- `PianoKeys`：琴鍵、熱鍵、即時按鍵回饋。
- `SheetDisplay` / `ScoreEditor`：譜面顯示與 JSON 編輯。
- `ScoreConverter`：MIDI、MusicXML、JSON、Slim JSON 的匯入與轉換。
- `ScoreLibrary`：Firebase 雲端曲庫。
- `InstrumentSelector`：樂器與音色選擇。

## 模組責任邊界

- 樂器發聲與排程問題歸 `06`；不要把 sample 載入、AudioContext、release 修正寫散到 UI 記憶。
- 視覺與互動狀態歸 `07`；版面問題先修 component/CSS，再評估是否影響資料流。
- 樂譜格式與轉檔歸 `03`；新增欄位前先確認 `scoreDocument.js`、`scoreToMidi.js`、`useScorePlayback.js` 都能理解。
- Firebase 與 GitHub 分別由 `04`、`05` 管理；涉及 Hosting base path 時兩份都要更新。

## 目前需注意的風險

- 部分舊檔曾出現亂碼，包含記憶文件與使用者可見文案；修改前需確認檔案編碼與字串語法。
- `dist`、`dist-fb`、`dist-gh` 是建置輸出，除部署驗證外不要把它們當主要來源。
- Firebase 有 Firestore 文件大小限制，大型譜面應使用 Slim JSON 或改以 Storage/Hosting URL 保存內容。
- GitHub Pages 需要 base path `/-_hina/`，Firebase Hosting 需要 base path `/`，兩者不可混用。
- Vite build 成功但會提示 `surges-slim.json` 同時被靜態與動態 import；若未來要優化首包，需整理 `src/hooks/useScoreState.js` 與 `src/data/importableScoreFiles.js` 的匯入關係。
