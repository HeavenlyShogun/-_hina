# Project Hina 目前系統總覽

最後更新：2026-05-22

## 技術現況

- 前端：React + Vite。
- 樣式：Tailwind CSS + Lucide React。
- 音訊：Web Audio API + `@tonejs/midi`，播放控制集中在 `src/services/playbackController.js` 與 `src/hooks/useScorePlayback.js`；音色取樣與合成集中在 `src/services/audioEngine.js`。
- 雲端：Firebase Auth + Firestore + Firebase Hosting。
- 狀態主軸：
  - 譜面主狀態：`src/hooks/useScoreState.js`
  - 音色設定：`src/contexts/AudioConfigContext.jsx`
  - 播放狀態：`src/contexts/PlaybackContext.jsx`

## 目前譜面系統

- 編輯器主格式是 JSON `version: "2.0"`。
- 主要結構：
  - `meta`
  - `transport`
  - `playback`
  - `source`
  - `tracks[].events[]`
- 播放與預覽前，所有來源都會經過 `normalizeScoreSource()` 正規化。
- 支援的來源：
  - 文字譜
  - JSON 譜
  - MIDI
  - MusicXML
  - Slim Score `version: "3.2-ultra-slim"`

## 頁面工作區順序

`src/App.jsx` 的工作區順序目前是：

1. 主畫面
2. 鍵盤
3. 節奏與調性調整
4. 譜面編輯
5. 譜面轉換
6. （已移除獨立演奏預覽與雲端曲庫區塊）

側欄 `Workspace` 導覽順序必須和實際可見區塊一致；目前不顯示獨立 `cloud-library` 導覽項。

## 主要頁面區塊

- `PianoRoom`
  - 主畫面、選曲、鍵盤入口、快速跳區塊。
- `SheetDisplay` / `ScoreEditor`
  - 譜面編輯、JSON 摘要、匯入、下載、存檔、重設。
- `ScoreConverter`
  - MIDI / MusicXML 單一檔案入口、拖放區、待上傳清單、覆蓋或接到後面、Firestore 批次上傳。
- `ScoreLibrary`
  - Firebase 曲庫列表元件仍保留在程式碼中，但目前主工作區不顯示獨立雲端曲庫區塊。
- `PianoKeys`
  - 鍵盤區內建 `Playback Timeline`，可拖曳定位，並提供「暫停 / 繼續」按鈕；主播放按鈕仍保留停止行為。
- 背景圖
  - 實際主背景由 `src/assets/galaxy.jpg` 提供，已從 600x435 本機重採樣為 2400x1740。
  - `public/images/galaxy.jpg.jpg` 與根目錄 `銀河系照片.jpg` 同步為同尺寸版本，避免不同部署入口使用舊低解析圖。

## 目前音色系統

- `src/components/InstrumentSelector.jsx` 顯示中文音色名稱。
- 樂器清單集中在 `src/constants/instruments.js` 的 `AVAILABLE_INSTRUMENTS`，UI 與音訊設定共用這份資料。
- `src/services/audioEngine.js` 目前採用樂器 adapter / registry 入口：
  - sampled 類型負責準備外部 sample set。
  - synthesized 類型不需下載檔案，直接使用 Web Audio oscillator / filter / ADSR preset。
  - 播放器仍只呼叫 `prepareTone()`、`scheduleNote()`、`playLiveNote()`，不需要知道樂器是取樣或合成。
- `src/services/audioEngine.js` 優先使用 MIDI.js / FluidR3_GM 取樣音色：
  - 鋼琴：`acoustic_grand_piano`
  - 小提琴：`violin`
  - 長笛：`flute`
  - 豎琴長音 / 豎琴短音：`orchestral_harp`
  - 空靈鼓：`steel_drums`
- `tongue-drum-electronic` 是額外的電子空靈鼓合成音色，不取代原本空靈鼓。
- 已加入可擴充電子音示範：
  - `retro-saw-synth`
  - `cozy-triangle-lead`
- 取樣來源需要瀏覽器能連到 `https://gleitz.github.io/midi-js-soundfonts/FluidR3_GM/`；若載入失敗，音訊引擎仍會 fallback 到原本的合成音色 preset。

## 目前轉換器狀態

- 不再以 `Current Payload` 當主要畫面。
- 主畫面是：
  - 單一拖放區
  - 拖放區內的 MIDI / MusicXML 多檔選擇按鈕
  - 待上傳清單
  - 明確的「上傳本批」與「清除本批」
- 已移除浮動狀態 pills、AI 輔助轉換區、MiniMax 操作區。
- 每筆轉換狀態直接顯示在 `Pending Uploads` 項目內。
- 轉換結果載入到編輯器有兩種動作：
  - 覆蓋到譜面編輯
  - 接到後面
- MIDI 匯入現在以「MIDI 播放器」邏輯為準：
  - `parseMidiToV2()` 會保留 MIDI 的 BPM、拍號、PPQ、tempo map、track、channel、instrument、programNumber、velocity。
  - 載入 JSON/MIDI 轉換譜時，`scoreDocument` 先讀檔案內 `transport` / `playback`，不要先套本機簡譜預設。
  - 固定音高來源保留原 MIDI note/frequency；鍵盤映射只做視覺輔助。
  - 轉換器清單與譜面摘要要顯示 MIDI preset 摘要，讓使用者能像 MIDI 播放器一樣檢查匯入結果。

## 譜面編輯區目前狀態

- 支援下載：
  - JSON
  - MIDI
  - 原始譜面
- JSON 譜面會顯示摘要卡：
  - 標題
  - 格式
  - BPM
  - 拍號
  - PPQ / Player preset
  - 軌道與事件數
- JSON 摘要中的軌道列表要優先顯示 MIDI/MusicXML 來源的 instrument、channel、programNumber，方便檢查是否符合匯入檔預設。
- 2026-05-22 已將譜面編輯區主要介面與說明改為中文，保留必要的格式關鍵字如 JSON、MIDI、MusicXML。

## 雲端曲庫定位

- Firebase 曲庫現在主要透過轉換器的批次上傳與編輯器存檔入口使用，不是大型譜面 CDN。
- 獨立 Cloud Library 主畫面區塊目前已從工作區移除。
- 大型譜面仍應優先轉成 Slim JSON 或採用靜態檔案方式，而不是直接把肥大 JSON 長期塞進 Firestore。
