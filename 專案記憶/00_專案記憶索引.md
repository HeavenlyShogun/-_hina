# universe rhythm recorder 專案記憶索引

最後更新：2026-09-30
核心版本：1.1.0 穩定版

本目錄為專案的軟體領域記憶系統，維持「1 份索引 + 10 份主題記憶 + 1 份工作接續記憶」。`工作接續記憶.md` 是唯一允許的滾動工作狀態檔，不取代主題記憶，也不再建立其他臨時紀錄或時間戳補丁檔。

---

## 記憶維護三大鐵律

1. **主題槽位固定（Hard Cap 10）**：主題記憶固定為 10 份。任何新功能、新腳本或需求更新，必須「就地合流（In-place Merge）」至對應主題檔，嚴禁新增 `11_...`、`12_...`；工作進度只更新 `工作接續記憶.md`。
2. **正文即時更新，不留覆蓋補丁**：發現規格變更時，直接覆寫主題檔正文，僅保留最新事實與關鍵決策，不採用「舊紀錄 + 後續補充修正」的堆疊寫法。
3. **軟硬邊界隔離**：本目錄只記錄前端軟體、資料流與通訊協議。實體線路、BOM 表、ESP32 韌體程式碼集中於 `外接硬體資訊/`，雙方僅透過 `09_外接硬體通訊與契約.md` 保持介面同步。

## 系統現行重要基準（Ground Truth）

- **版本與環境**：穩定版 `1.1.0`，核心音訊套件為 `tone@15.1.22`。
- **譜面入口**：核心格式為 JSON v2 與 Slim JSON；`public/score-library-manifest.json` 目前列出 47 首曲目，外部格式（MIDI/MusicXML/MXL）一律由轉檔產線處理為 Payload。
- **雲端與離線**：Firestore 啟用 Persistent Local Cache；編輯器內建 3 秒 Debounce 背景同步；公開譜面透過 `publicScores` 與 `?scoreId=` 存取。
- **音訊與排程**：播放期間**鎖定樂器切換**；主 BPM 滑桿使用 `requestAnimationFrame` 節流；節拍器 Click 走獨立 Web Audio，不佔用播放排程。
- **目前驗證**：2026-09-30 `npm run build:firebase` 成功；Vite 分割 React、Firebase、Tone.js、MIDI、圖示與狀態管理 chunk。Firebase chunk 為 548.65 kB，`chunkSizeWarningLimit` 已設為 600 kB，因此 build 不再顯示 chunk size 警告；這調整的是警告門檻，不代表 Firebase chunk 已縮小。
- **硬體介接狀態**：外部主板需求為 3 排實體琴鍵本機發聲及自動播放；ESP32 韌體原始碼位於 `外接硬體資訊/hina_lyre_main.ino`。
