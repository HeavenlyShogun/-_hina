# 基礎組成元素與作業位置

最後更新：2026-06-05

本檔記錄專案的基礎目錄、設定檔、腳本與日常維護入口。

## 根目錄

- `package.json`：npm scripts、dependencies。
- `vite.config.js`：Vite build、base path、alias 或 plugin 設定。
- `firebase.json`：Firebase Hosting 設定。
- `firestore.rules`：Firestore 權限規則。
- `.env.example`：環境變數範例。
- `README.md`：一般說明。
- `GEMINI.md`：協作/代理記錄。
- `project-progress-plan.txt`、`專案現況總結.md`：歷史規劃與狀態摘要。

## 原始碼目錄

- `src/components`：可重用 UI component。
- `src/pages`：頁面級 component。
- `src/hooks`：React hooks 與狀態封裝。
- `src/contexts`：跨 component context。
- `src/services`：Firebase、音訊、播放等服務。
- `src/utils`：譜面、MIDI、MusicXML、DOM 效果等工具。
- `src/data`：內建曲目與可匯入譜面索引。
- `src/constants`：音樂常數、樂器清單。
- `src/config`：品牌與 app 設定。
- `src/config/scoreLibraryPaths.js`：預設曲庫根路徑、MIDI 路徑、slim JSON 路徑與預設 slim 檔名。

## 資料與工具

- `風物之琴譜`：原始曲譜、轉檔產線、匯入用 slim-json/midi。
- `樂理底層邏輯`：樂理與底層規則資料。
- `music_work`：分析與中間產物。
- `scripts`：build、preview、score migration、MIDI/slim 工具。
- `sounds`：音訊素材或預留音色資源。

## 建置輸出

- `dist`：一般 Vite build 或歷史輸出。
- `dist-fb`：Firebase Hosting build。
- `dist-gh`：GitHub Pages build。
- `build`：歷史或工具輸出。

建置輸出通常不作為原始碼修改來源，除非正在驗證部署結果。

## 建議檢查順序

1. `git status --short`
2. `npm.cmd run build:firebase`
3. `npm.cmd run build:pages`
4. 需要 UI 驗證時再啟動 dev server 或 preview。

## 可用驗證指令

- Firebase build：`npm.cmd run build:firebase`
- GitHub Pages build：`npm.cmd run build:pages`
- 譜面壓力檢查：`npm.cmd run scores:stress`
- MIDI slim 工具：`npm.cmd run scores:slim:midi`

## 本機新增 MIDI 串接入預設選單流程

1. 把新 MIDI 放到 `風物之琴譜/縮小版可匯入譜面/midi/`。
2. 若同一首有不同語言檔名，先用 `Get-FileHash -Algorithm SHA256 -LiteralPath <檔案1>,<檔案2>` 確認是否為 duplicate；前端只需接一份 slim JSON。
3. 用 `node scripts/slim-midi-score.mjs --input="<midi路徑>" --output="風物之琴譜/縮小版可匯入譜面/slim-json/<slug>-slim.json" --id="<slug>" --title="<曲名>" --display-title="<曲名>"` 轉成 slim JSON。
4. 到 `src/data/importableScoreFiles.js` 的 `IMPORTABLE_SCORE_ORDER` 加入新的 `<slug>-slim.json`，控制預設選單排序。
5. 若預設譜面數量有上限，新增一首時必須同步確認是否要移除或排除其他 slim JSON。
6. 執行 `npm.cmd run build:firebase` 與 `npm.cmd run build:pages` 驗證；部署前確認 AppHeader 的「可匯入譜面」數量符合預期。
