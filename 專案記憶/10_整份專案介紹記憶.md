# universe rhythm recorder 整份專案介紹記憶

最後更新：2026-06-05

## 專案定位

universe rhythm recorder 目前對外名稱為 `universe rhythm recorder`，標語為 `universe rhythm recorder`。它不是單純的網頁鋼琴，而是一個以星空介面包裝的單頁音樂工作台，整合即時演奏、譜面播放、節奏與調性調整、JSON 譜面編輯、MIDI / MusicXML / MXL 轉檔、Firebase 雲端曲庫與雙平台部署。

目前穩定版本為 `1.1.0`。版本號由 `package.json` 管理，經 `vite.config.js` 注入 `__APP_VERSION__`，畫面右下角顯示版本。

## 技術骨架

- 前端：React 19、Vite 7、Tailwind CSS、lucide-react。
- 音訊：Web Audio API 自製音訊引擎，包含 sampler、合成器 fallback、compressor、reverb bus、voice lifecycle 與 sample cache。
- 譜面：V2 JSON、V3 相容分支、`3.2-ultra-slim` Slim JSON；使用者直接讀取入口目前只接受 JSON / Slim JSON。
- 轉檔：`@tonejs/midi` 解析 MIDI，內建 MusicXML / MXL 讀取與 Slim JSON 轉換。
- 雲端：Firebase Auth + Firestore，分為完整譜面與摘要文件。
- 部署：GitHub Pages 輸出 `dist-gh`，Firebase Hosting 輸出 `dist-fb`。

## 使用者工作流

主畫面由 `src/App.jsx` 組裝，核心演奏區由 `src/pages/PianoRoom.jsx` 承接。使用者可從首頁曲庫載入 Slim JSON 歌曲，或在轉檔區拖放 MIDI、MusicXML、MXL，轉成可播放 JSON 後載入目前譜面。

單檔轉檔會直接載入編輯器，多檔轉檔會先進入本機暫存清單。暫存曲目可以覆蓋目前譜面、接到目前譜面後方，也可以批次上傳到 Firestore 曲庫。MusicXML / MXL 多檔可依檔名自然排序合併，MIDI 轉檔保留 BPM、拍號、PPQ、tempo map、track、channel、instrument 與 velocity；預設可過濾 Channel 10 鼓軌。

譜面編輯區負責 JSON 內容、曲名、參考資料、匯入匯出與雲端存檔。存檔前會把目前節奏、調性、音色、音量、殘響、移調與升記號設定寫回譜面文件。

播放中會鎖定樂器切換，避免排程期間更改 tone。Rhythm 控制面板另有獨立節拍器，可開關並調整 30.0 到 240.0 BPM；節拍器 click 不走譜面播放排程。

## 播放與節奏系統

播放核心在 `src/services/playbackController.js` 與 `src/hooks/useScorePlayback.js`。它使用 tick-based transport，不依賴鬆散的逐音 `setTimeout`。目前支援播放、暫停、繼續、從頭、seek、scrub、播放速率與鍵位高亮。

排程以 `audioContext.currentTime` 為基準，使用 lookahead scheduling；tempo map 會影響 tick 與秒數的換算。事件正規化後的核心欄位是 `tick` / `durationTicks` / `k` / `v` / `noteName` / `frequency` / `trackId`，播放流程應繼續以這套 canonical event 為準。

主 BPM 控制已用 `requestAnimationFrame` 節流，滑桿連續拖動時不會在同一 frame 內重複推送狀態；`ControlPanel` unmount 時需取消尚未執行的 BPM animation frame。

## 譜面模型

主要入口在 `src/utils/score.js`、`src/utils/scoreDocument.js`、`src/utils/midiToV2.js`、`src/utils/musicXmlToSlim.js`。目前使用者匯入檔案時，非 JSON 檔會被要求先走轉換區；文字鍵盤譜與數字譜不再是正式讀取格式。

底層仍保留 legacy / numbered parser 與分析工具，主要作為相容與工程參考，不應重新包裝成主要使用者入口。新的譜面功能應優先擴充 JSON / Slim JSON schema。

調性目前只開放可對應現實樂理的大調與自然小調。固定音高來源如 MIDI、MusicXML、Slim JSON 會優先保留原始 MIDI 音高，再依全域移調處理。

## 音色系統

音訊核心在 `src/services/audioEngine.js`，樂器定義在 `src/constants/instruments.js`，樂器選擇 UI 在 `src/components/InstrumentSelector.jsx`。目前音色不是單一 oscillator，而是 preset + adapter 架構，可走 sampler 或 synthesized fallback；2026-06-03 起前端 tone selection 收斂為單一 tone id，舊譜面或舊 UI 狀態若帶入 tone array，只取第一個合法 tone，避免多音色疊加造成切換錯誤。

重點音色包含 `piano`、`midi-original`、`bright-acoustic-piano`、`electric-guitar-clean`、`guitar`、`harp`、`flute`、`drums`、`tongue-drum`、`tongue-drum-electronic`、`retro-saw-synth`、`cozy-triangle-lead`、`classic`。`midi-original` 會盡量依 MIDI track metadata 對應 GM soundfont sample set；sample 無法載入時會回到合成器路徑。

原聲類 Piano / Guitar / Harp / Flute 使用 `tonejs-instruments` 的 `.wav` sample path，Drums 使用 Oramics Pearl acoustic drums sample；電子類 `tongue-drum-electronic`、`retro-saw-synth`、`cozy-triangle-lead` 明確走 `Tone.PolySynth`。音訊引擎有 sample loading timeout、direct sample fallback、MIDI.js soundfont 載入、Salamander piano sample、鋼琴 timbre curve、hammer noise、reverb、compressor、voice stealing。`AudioEngine.MAX_VOICES` 目前為 72。

密集播放修正已併入 `06_樂器發聲與音訊引擎記憶.md`。`playbackController` 會計算同一 tick 的 `simultaneousNotes`，`audioEngine.resolveRenderConfig()` 以 `1 / sqrt(simultaneousNotes)` 產生 `denseGainScale`，並以 `DENSE_NOTE_GAIN_FLOOR = 0.16` 保留下限，降低多音軌和弦短時間齊發時的爆音風險。

## UI 與視覺

視覺主軸是星空背景與半透明工作台。背景資產主要在 `src/assets/galaxy-background.jpg`，底部 `Background Board` 用來放專案介紹與公告，並可手動淡化文字只保留背景欣賞。

主畫面提供快速跳轉側欄，區塊包含主畫面、鍵盤、節奏調性、譜面編輯、譜面轉換、背景。整體 UI 有 `normal` / `clear` 面板模式，點背景可降低介面存在感。

`src/assets/galaxy.jpg`、`src/assets/galaxy-background.jpg`、`public/images/galaxy.jpg.jpg`、`galaxy.png` 都已納入 git 追蹤。`public/images/galaxy.jpg.jpg` 是靜態兼容資產，目前程式碼沒有直接引用。

## 雲端與部署

Firebase 邏輯在 `src/services/firebase.js` 與 `src/hooks/useCloudScores.js`。Firestore rules 限制資料在 `artifacts/{appId}/users/{userId}/scores` 與 `scoreSummaries`，要求登入且只能讀寫自己的資料。

建置與部署指令：

- 本機開發：`npm run dev`
- 區網開發：`npm run dev:host`
- GitHub Pages：`npm run build:pages`
- Firebase Hosting：`npm run build:firebase`
- Firebase deploy 前會由 `firebase.json` predeploy 自動跑 `npm run build:firebase`

GitHub Pages 使用 `/-_hina/` base path，Firebase Hosting 使用 `/`。Firebase Hosting headers 目前包含 noindex、no-referrer、nosniff。

## 曲庫與資料夾

內建曲庫來源在 `風物之琴譜/縮小版可匯入譜面/slim-json/`，由 `src/data/importableScoreFiles.js` 透過 `import.meta.glob` 動態掛入。預設 slim 譜面目前為 20 首，保留 `tada-koe-hitotsu-slim.json`；`guitar-loneliness-and-blue-planet-slim.json`、`seiza-ni-naretara-slim.json`、`zattou-bokura-no-machi-slim.json` 不作為目前預設 slim 譜面。

`風物之琴譜/縮小版可匯入譜面/midi/` 保留 MIDI 來源；新增本機 MIDI 後，先用 `scripts/slim-midi-score.mjs` 轉出 `slim-json/<slug>-slim.json`，再視需求把檔名加入 `src/data/importableScoreFiles.js` 的 `IMPORTABLE_SCORE_ORDER`。預設曲庫根路徑集中在 `src/config/scoreLibraryPaths.js`，slim metadata 會帶出 `libraryPath` 與 `defaultMidiPath`。`風物之琴譜/轉檔產線/` 與根目錄 Python / Node 腳本保留轉檔與資料整理用途。

## 目前風險與維護原則

- Vite 曾提示 `surges-slim.json` 同時被靜態與動態 import，屬分包警告，不是建置失敗。
- Vite 仍提示主 chunk 超過 500 kB，屬效能警告；目前未改動分包策略。
- 修改譜面讀取時，不要把舊文字譜重新開回正式入口；目前產品方向是 JSON / Slim JSON + 轉檔區。
- 修改播放時，維持 canonical event、tick transport、tempo map 與 lookahead scheduler。
- 修改音色時，延續 `audioEngine` preset / adapter 架構，不要把音色細節散到 UI；UI 只保存單一 tone id，避免 tone array 重新引入多音色疊加問題。
- 部署前固定驗證 `npm run build:firebase` 與 `npm run build:pages`。
