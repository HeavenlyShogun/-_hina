universe rhythm recorder 目前系統總覽

最後更新：2026-09-19

universe rhythm recorder 是以 React + Vite 建立的風物之詩琴/樂譜工作台，核心能力包含樂譜編輯、播放預覽、MIDI/MusicXML 轉檔、雲端曲庫，以及 Firebase/GitHub 雙部署。

技術棧

前端：React 19、Vite 7、Tailwind CSS、Lucide React。

音訊：Web Audio API、@tonejs/midi、自製 audioEngine 與播放排程。

資料：JSON v2 樂譜、Slim JSON、MIDI、MusicXML/MXL。

雲端：Firebase Auth、Firestore（具備離線持久化快取）。

部署：GitHub Pages 與 Firebase Hosting 分開建置。

核心作業位置

App 入口：src/App.jsx

前端入口：src/main.jsx

全域樣式：src/index.css

音訊引擎：src/services/audioEngine.js

播放控制：src/services/playbackController.js

樂譜載入與快取：src/services/scoreLibraryService.js (負責 Manifest 與 IndexedDB 快取)

樂譜狀態：src/hooks/useScoreState.js

播放 hook：src/hooks/useScorePlayback.js

Firebase service：src/services/firebase.js

樂器定義：src/constants/instruments.js

系統資料流

曲目來源：由 scoreLibraryService.loadLibraryManifest() 非同步取得曲庫清單，點擊時透過 fetchScoreBySlug 優先從 IndexedDB 快取讀取，無快取則從靜態路徑下載並存入快取；亦支援使用者 JSON 或 MIDI/MusicXML 轉檔匯入。

載入與轉換：ScoreConverter、ScoreEditor 或 useScoreState 將來源整理成可載入 payload。

資料正規化：score.js / scoreDocument.js 正規化為 editor 與播放共用的 canonical 結構。

播放計畫：useScorePlayback 依目前 tempo、playback config、audio config 建立計畫。

時間軸與發聲：playbackController 負責 tick 與時間排程，audioEngine 依 tone 載入 sample 或啟用合成 fallback 後發聲。

雲端同步：儲存時由 useCloudScores / firebase.js 寫入 Firestore 的完整文件與摘要文件。

播放中會由 App.jsx 將 isPlaying 傳入 PianoRoom，再以 isPlaybackActive 鎖定 InstrumentSelector，避免排程期間切換 tone 造成音訊狀態不一致。主 BPM 控制已用 requestAnimationFrame 節流。

主要功能區

PianoRoom：主畫面、特色曲目與工作區入口。

PianoKeys / SheetDisplay：演奏、播放時間軸與譜面摘要工作區。

ScoreConverter：MIDI、MusicXML、JSON、Slim JSON 的匯入與轉換。

ScoreLibrary：Firebase 雲端曲庫。

ControlPanel：BPM、拍號、音量、殘響、主音、大小調與獨立節拍器。

目前需注意的風險

部分舊檔曾出現亂碼，包含記憶文件與使用者可見文案；修改前需確認檔案編碼與字串語法。

dist、dist-fb、dist-gh 是建置輸出，除部署驗證外不要把它們當主要來源。

Firebase 有 Firestore 文件大小限制，大型譜面應使用 Slim JSON 或改以 Storage/Hosting URL 保存內容。

GitHub Pages 需要 base path /-_hina/，Firebase Hosting 需要 base path /，兩者不可混用。

Vite 主 App Chunk 仍會超過 500 kB 警告標記（但曲庫 JSON 47 首歌已成功抽離，不再污染 bundle）。

Production build 需要 tone@15.1.22 存在於 node_modules。
