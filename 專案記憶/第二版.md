# 第二版：新版 canonical / 簡譜時值邏輯

更新日期：2026-05-09

本檔記錄 Project Hina 第二版鋼琴／風物之琴彈奏邏輯。說「第二版」、「2 版」或「新版邏輯」時，指本檔定義。

## 狀態

目前主線。

## 核心定位

第二版先把譜面正規化為 canonical event，再交給顯示、播放器與練習判定。所有輸入格式最後都必須轉成 canonical event，播放器與譜面顯示層只依賴正規化後的事件資料。

第二版不使用「四格」、「拍格」或任何固定格子作為內部資料模型。音樂在程式邏輯中必須視為連續時間軸，每個音符以絕對起始 tick 與持續 tick 表示；播放層可再展開為 `note_on` / `note_off` 動態事件。

## 對應格式與參數

| 項目 | 定義 |
|---|---|
| text format | `numbered-text@1` |
| JSON score | JSON `version: "2.0"` |
| duration model | `startTick`、`durationTicks` |
| playback event model | `note_on`、`note_off` |
| resolution | `PPQ = 480` |

## 規則

| 規則 | 記憶定義 |
|---|---|
| 時間基準 | `PPQ = 480`，一個四分音符等於 480 ticks。4/4 一小節為 `4 * 480 = 1920` ticks。 |
| 內部時值 | 新版文字譜可接受以一拍 `1.0` 為單位的輸入，但 parser 進入內部模型後必須轉成整數 tick。不要用 float 累加作為最終時間軸。 |
| 小節驗證 | 例如 4/4 每小節必須等於 `1920` ticks；遇到 `|` 時應檢查，不應默默補齊或略過錯誤。 |
| 音高 | 簡譜 `1 2 3 4 5 6 7` 表示級數，`0` 表示休止。 |
| 調性 | `globalKeyOffset` 表示主音相對 C 的半音偏移，`scaleMode` 表示 major / minor。 |
| 升降與八度 | `#` / `b` 處理臨時記號，`'` / `,` 或 `+` / `-` 處理八度位移。 |
| 多聲部 | 左右手或多聲部用不同 `trackId` 保存，各 track 分別驗證拍數，播放前合併 canonical event stream。多個音可有相同 `startTick`，代表同時發聲。 |
| canonical 欄位 | 核心欄位包含 `startTick`、`durationTicks`、`k`、`v`、`velocity`、`frequency`、`noteName`、`trackId`。`time`、`durationSec` 只能是依 tempo 推導出的播放欄位，不可作為 canonical 時間來源。 |
| 目標 | 讓匯入、顯示、播放、轉調、練習判定與測試都使用同一份事件合約。 |

## 第二版必須解決的問題

### 解析度與切分音

禁止把 4/4 拍的一小節切成四
格後把音符塞進格子。這種模型無法乾淨表示從第一拍後半開始、延續到第二拍後半的切分音，也會讓跨格線、跨小節、附點音符變成複雜的例外。

第二版的正確模型是絕對時間軸：

- `startTick`：音符開始的絕對 tick。
- `durationTicks`：音符持續的 tick 數。
- `endTick = startTick + durationTicks`。

小節只是一段 tick 範圍。例如 4/4、`PPQ = 480` 時，第 1 小節為 `[0, 1920)`，第 2 小節為 `[1920, 3840)`。音符是否跨小節不影響資料結構。

### 多音並行

第二版必須支援 polyphony。鋼琴和風物之琴都不能假設單手同一時間只能有一個音。和弦或重疊聲部用多筆 canonical note 表示，這些 note 可以共享相同的 `startTick`。

例如 C 大三和弦：

```js
[
  { startTick: 0, durationTicks: 480, noteName: "C4", velocity: 64, trackId: "right" },
  { startTick: 0, durationTicks: 480, noteName: "E4", velocity: 64, trackId: "right" },
  { startTick: 0, durationTicks: 480, noteName: "G4", velocity: 64, trackId: "right" }
]
```

左右手分離時只需保留不同 `trackId`，例如 `left` 與 `right`。播放前可以合併排序，也可以播放時同時掃描兩個 track。

### 資料格式一致性

第二版 parser 不應讓音符與休止符使用不對稱格式，例如音符寫成 `(C4, 1.0)`、休止符寫成 `R0.5`。所有 token 在 parser 階段必須轉成同一種結構。

休止符在 canonical 時間軸中原則上不需要成為播放 note。休止符只是前一個 `note_off` 到下一個 `note_on` 之間的空白。若匯入格式需要保留休止符作為中介資料，也必須使用一致結構，例如：

```js
{ startTick: 480, durationTicks: 240, isRest: true, trackId: "right" }
```

進入播放事件流時，休止符不產生音訊事件，只推進時間。

### 三連音與整數 tick

第二版不得依賴 float 時間累加判斷左右手同步。四分、八分、十六分、三十二分音符只覆蓋 `2^n` 的切分，無法完整處理三連音。

`PPQ = 480` 的理由：

| 音值 | ticks |
|---|---:|
| 四分音符 | 480 |
| 八分音符 | 240 |
| 十六分音符 | 120 |
| 三連音一個音 | 160 |

三連音可以被整數表示，避免 `0.3333...` 拍在多小節累積後造成 desync。

## 播放事件模型

canonical note 是分析與儲存單位；播放時可展開為動態事件：

```js
const timelineEvents = [
  { tick: 0, type: "note_on", note: "C4", velocity: 64 },
  { tick: 0, type: "note_on", note: "E4", velocity: 64 },
  { tick: 0, type: "note_on", note: "G4", velocity: 64 },
  { tick: 480, type: "note_off", note: "C4" },
  { tick: 480, type: "note_off", note: "E4" },
  { tick: 480, type: "note_off", note: "G4" },
  { tick: 480, type: "note_on", note: "D4", velocity: 80 }
];
```

分析音符佔有時間時，不需要數格子：

```txt
Duration = Note_Off_Tick - Note_On_Tick
```

若結果為 `120` ticks，代表十六分音符；若結果為 `160` ticks，代表三連音中的一個音。

## 使用原則

- 新功能優先接到第二版主線。
- 不論來源格式為何，播放與顯示層最終應吃 canonical event。
- 第二版是目前可維護、可驗證、可支援多聲部的主要資料模型。
- 第二版所有新增 parser、播放器、練習判定與匯出功能，都必須以整數 tick 的絕對時間軸為準，不能回退到固定格子模型。
