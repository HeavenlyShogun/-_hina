# 譜面系統與轉換記憶

最後更新：2026-05-22

## 目前有效的譜面格式

### 編輯器主格式

- `version: "2.0"`
- 結構：
  - `meta`
  - `transport`
  - `playback`
  - `source`
  - `tracks[].events[]`

### 支援的輸入來源

- 文字譜
- JSON 譜
- MIDI
- MusicXML
- Slim Score `version: "3.2-ultra-slim"`

### 正規化入口

- `src/utils/score.js`
- 主要方法：`normalizeScoreSource()`
- 所有播放、預覽、合併、轉換後載入，都應以這裡為準

## Slim Score 現況

- 前端主曲庫入口：`風物之琴譜/縮小版可匯入譜面/slim-json/*-slim.json`
- Slim Score 仍是重要來源格式，但不是編輯器直接維護格式。
- 一旦載入編輯器、合併、匯出或雲端存檔，主流程仍以 editor JSON v2 為核心。

## 編輯器匯出與介面

位置：`src/components/SheetDisplay.jsx` + `src/App.jsx`

目前支援：

- JSON
- MIDI
- 原始譜面

規則：

- 若目前是 JSON 譜，下載 JSON 直接輸出目前內容。
- 若目前是文字譜，下載原始譜面輸出文字內容。
- 若下載 MIDI，會先把目前譜面整理成可輸出的 score JSON，再轉成 `.mid`。
- 譜面編輯區主要介面文字以中文為主：
  - JSON 摘要顯示「譜面摘要、標題、格式、速度、拍號、軌道、事件、音符」。
  - 大型 JSON readonly 文字摘要也以中文顯示。
  - 必要格式名仍保留 JSON、MIDI、MusicXML、Tick 等技術詞。
- 已移除 `app-shell` 對 UI panel、button、footer 的全域文字陰影；鍵盤音名也不再使用文字陰影，避免中文與小字模糊。

## 轉換器目前行為

位置：`src/components/ScoreConverter.jsx`

### 已確定的 UI 結構

- 單一拖放區，支援 MIDI / MusicXML
- 拖放區內整合「選擇 MIDI」與「選擇 MusicXML/MXL」
- Pending Uploads
- Pending Uploads 標題列提供「上傳本批」與「清除本批」
- 每筆項目顯示來源格式、檔名、大小、轉換摘要與 Firestore 待上傳狀態
- 轉換器上方有三步驟中文提示：匯入、檢查、套用。

### 已移除的舊概念

- `Current Payload` 不再是轉換器主畫面。
- 浮動狀態標籤 pills 不再顯示 MIDI / MusicXML 是否已匯入。
- AI 輔助轉換區已從 `ScoreConverter.jsx` 移除。
- MiniMax 操作區已從 `ScoreConverter.jsx` 移除。

### 手動草稿輸入

- 目前轉換器不保留手動貼譜 / 貼 JSON / AI 草稿入口。
- 轉換器定位收斂為 MIDI / MusicXML 檔案轉換與 Firestore 批次上傳。

## 覆蓋與接到後面

### 覆蓋到譜面編輯

- 直接以新的 payload 取代目前 editor 內容。

### 接到後面

- 位置：`src/App.jsx`
- 主要邏輯：`mergeConvertedScorePayloads()`
- 規則：
  - 先把目前譜面與新譜面都用 `normalizeScoreSource()` 轉成 canonical event
  - 以目前譜面末尾 tick 作為偏移量
  - 將新譜面的事件整體後移
  - 再重建成 editor 可接受的 JSON v2 `tracks[].events[]`
- 用途：
  - 同一首歌切成多檔後依序合併
  - 不是字串拼接，而是時間軸合併

## MIDI 播放器式預設同步

- MIDI 匯入的基準是「先相信匯入檔自己的播放設定」，再讓本機控制面板做手動微調。
- `src/utils/midiToV2.js` 匯入時應保留 `transport.bpm`、拍號、PPQ、`playback.tempoMap`、`playback.fixedPitch`、track channel、instrument、programNumber、note velocity、frequency、MIDI note。
- `src/utils/scoreDocument.js` 載入 JSON 來源時要先合併 content 內的 `transport` / `playback`，避免本機 `DEFAULT_SCORE_PARAMS` 先蓋掉 MIDI preset。
- `src/services/playbackController.js` 的 tempo map 解析需支援 `{ startTick, bpm, secondsPerTick }`、`{ ticks, bpm }`、`[tick, bpm]`。
- MIDI / MusicXML / slim score 這類固定音高來源，播放時音高以 note/frequency 為準；鍵盤映射只做視覺輔助。
- 轉換器與譜面摘要 UI 要顯示 MIDI preset 摘要，例如 BPM、拍號、PPQ、tempo changes、active tracks、instrument/channel/program。

## 音色擴充架構

- 樂器定義集中在 `src/constants/instruments.js` 的 `AVAILABLE_INSTRUMENTS`。
- 新增樂器時先決定 `type`：
  - `sampled`：外部 soundfont / WAV / MP3 / AudioBuffer 類取樣樂器。
  - `synthesized`：Web Audio oscillator / filter / envelope 即時計算音色。
- `src/services/audioEngine.js` 透過 instrument adapter / registry 準備音色；播放器只呼叫 `prepareTone()`、`scheduleNote()`、`playLiveNote()`。
- `TONE_PRESETS` 仍負責聲音參數，例如 sampleSet、oscillator type、ADSR、filter、harmonics、vibrato、release。
- `InstrumentSelector.jsx` 不再手寫固定三個按鈕，改從 `listAvailableInstruments()` 產生按鈕。
