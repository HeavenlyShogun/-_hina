# 譜面系統與轉換記憶

最後更新：2026-05-29

本檔集中管理樂譜格式、轉換流程、匯入匯出與相關除錯入口。

## 支援格式

- 1.1 起不再讀取舊版鍵盤文字譜或數字譜；使用者入口收斂為 JSON/Slim JSON，以及 MIDI / MusicXML / MXL 轉檔後 JSON。
- JSON v2：目前編輯器與播放核心的主要結構。
- MIDI：透過 `@tonejs/midi` 解析後轉成 v2。
- MusicXML / MXL：轉成 Slim JSON 或可匯入 payload。
- Slim Score：`version: "3.2-ultra-slim"`，用於大型曲目與批次匯入。

## JSON v2 核心結構

- `meta`
- `transport`
- `playback`
- `source`
- `tracks[].events[]`

轉換或合併後應經過 `normalizeScoreSource()` 或 `createScoreDocument()` 類工具，避免同一曲目在播放、顯示、儲存時使用不同結構。

## 欄位責任

- `meta`：標題、顯示名稱、來源與匯入摘要。
- `transport`：BPM、拍號、PPQ/resolution、tempo map 的基準資料。
- `playback`：tone、globalKeyOffset、scaleMode、reverb、fixedPitch 等播放偏好。
- `source`：保留原始來源格式、檔名、轉檔註記與可追溯資料。
- `tracks[].events[]`：真正播放與匯出用事件，應保留 tick、duration、note、velocity、track/channel/program 資訊。

## 匯入與合併流程

- 單檔匯入：解析來源後建立 v2 或 slim payload，再送入 editor 狀態。
- 覆蓋到譜面編輯：新的 payload 取代目前 editor 內容。
- 接到後面：目前譜面與新譜面都先 normalization，再依目前末尾 tick 偏移新事件，避免字串拼接造成節奏錯位。
- 批次上傳：轉檔候選先進 Pending Uploads；真正寫入 Firestore 前仍需走 `firebase.js` 的大小與資料檢查。

## MIDI 轉檔規則

- 保留 BPM、PPQ、tempo map、track、channel、instrument、programNumber、velocity。
- note event 需保留 tick 與 duration，並盡量保留 MIDI note/frequency。
- 若 MIDI 有多軌，合併時需避免 tick 排序錯亂與 active track 遺失。
- UI 應顯示可判斷轉檔品質的摘要：BPM、PPQ、tracks、channels、programs、event count。
- MIDI / MusicXML / slim score 這類固定音高來源，播放時優先使用 note/frequency；琴鍵映射主要提供視覺輔助。
- `scoreDocument.js` 載入 JSON 來源時需先尊重檔案內 `transport` / `playback`，再套用本機控制面板覆寫。

## MusicXML / MXL 規則

- MXL 是壓縮包，解析前需展開主要 MusicXML 檔。
- MusicXML 可能包含多聲部、多譜表、反覆記號與裝飾音；轉成 Slim JSON 時需明確標示未支援資訊。
- 大型 MusicXML 不應直接塞入 Firestore 完整內容，需先壓縮為 Slim JSON 或改存 URL。
- 2026-05-29 已強化 `musicXmlToSlim.js`：用 `localName` 解析 MusicXML，避免命名空間造成 `querySelector` 失效；同時處理 UTF-8 BOM。
- 2026-05-29 已強化 `musicXmlArchive.js`：MXL 讀取會解析 `META-INF/container.xml`，支援 `deflate-raw` 與 `deflate` 嘗試解壓，並保留來源格式為 `musicxml` 或 `mxl`。
- 目前轉換器支援 `score-partwise`；`score-timewise` 會明確報錯，尚未轉換為可播放 notes。

## AI 輔助轉檔定位

- `src/utils/scoreConversionAssist.js` 保留為 AI 轉譜輔助工具入口。
- 若重新啟用 AI UI，輸出必須符合 JSON v2，使用整數 tick 與 `transport.resolution`。
- AI 結果不得直接視為可信譜面；需經格式檢查、normalization、摘要檢查，再允許覆蓋、接續或上傳。

## 除錯入口

- 格式錯誤：先檢查 `scoreDocument.js` 與 `score.js` 的 normalization。
- 播放錯位：檢查 tick、PPQ、tempo map 與 `playbackController.js`。
- 匯出 MIDI 錯誤：檢查 `scoreToMidi.js` 是否收到 canonical events。
- 雲端儲存失敗：檢查 `04_Firebase與雲端曲庫記憶.md` 的大小限制與資料路徑。
- MusicXML/MXL 匯入失敗：先看 `readMusicXmlFile()` 是否讀到主譜檔，再看 `convertMusicXmlToSlim()` 是否能找到 `score-partwise > part`。
- Vite 分包警告：`surges-slim.json` 同時被 `useScoreState.js` 靜態載入、被 `importableScoreFiles.js` 動態載入；功能可用，但會影響 chunk 拆分。
