# 譜面系統與轉換記憶

最後更新：2026-10-08

本檔集中管理譜面格式、轉換流程、回歸驗證與雲端遷移原則。

## 核心資料流

> Hina 以 MIDI 作為正式譜面來源與交換標準，以 Canonical Event Model 作為執行與編輯模型，以 Slim JSON 作為輕量儲存與傳輸格式；MusicXML / MXL 僅作為 Legacy Import。

- MIDI：正式來源與交換格式。
- Slim JSON（version: 3.2-ultra-slim）：目前推薦的儲存與匯入 payload。
- Canonical Runtime Events：前端播放與編輯流程的標準事件模型。
- MusicXML / MXL：舊譜面匯入來源；轉換後也應形成 Slim payload。
- Metadata 語意分開：sourceFormat 表示最初來源，storageFormat 表示當前儲存表示，version 表示資料結構版本。例如 sourceFormat=midi、storageFormat=hina-slim-score@3.2、version=3.2-ultra-slim。

## 轉換與程式位置

- MIDI -> Slim：src/utils/midiToSlim.js 的 parseMidiToSlim()，供瀏覽器匯入使用。
- Slim -> Runtime：src/utils/score.js 的 normalizeScoreSource()；V2/V3 parser 仍保留，待 migration 與 Phase 4 DAW 驗證後再搬到 src/utils/legacy/。
- Runtime / Slim -> MIDI：src/utils/scoreToMidi.js 的 scoreJsonToMidi() / scoreJsonToMidiBytes()。
- MusicXML/MXL -> Slim：src/utils/musicXmlToSlim.js 與 src/utils/musicXmlArchive.js。
- 匯入 UI：src/components/ScoreConverter.jsx；MIDI 主流程使用 Slim converter，MusicXML 為 legacy import。
- 譜面封裝與 Firebase 欄位：src/utils/scoreDocument.js、src/services/firebase.js。
- V2 MIDI converter src/utils/midiToV2.js 已標示 deprecated，主流程不再使用；暫不刪除。

## MIDI 回歸與 Golden Fixtures

Round-trip 目標：MIDI -> Slim 3.2 -> Canonical Runtime Events -> MIDI。固定測試來源位於 tests/fixtures/midi/：

- basic.mid：單軌基本音符。
- tempo-map.mid：PPQ 960、快速 tempo map 與 4/4、3/4、7/8 拍號變化。
- multi-track.mid：多軌、多樂器、空軌，以及同軌 Program Change。
- drums.mid：Channel 10（MIDI 零起始 channel 9）鼓軌。
- edge-cases.mid：1 tick 音符、同 tick 和弦、velocity 邊界。

npm run fixtures:midi:generate 可確定性重建原始樣本；npm run fixtures:midi:export 將經 Slim 與 Runtime 正規化後的 MIDI 輸出至 tests/fixtures/midi/roundtrip/，供 DAW A/B 比較。npm run test:unit 執行 round-trip 與 golden fixture 測試。目前 8 項測試通過，另有 PPQ 96/480/960、tempo map、拍號、多軌、鼓軌、極短音符、和弦及 Program Change 覆蓋。

DAW 聽感與視覺檢查尚未執行。SOP 位於 tests/fixtures/midi/README.md；須人工檢查時間軸、事件與 velocity、軌道/channel、Program Change 和實際播放聽感，完成後才可將 Phase 4 標為完成。

## Firebase 舊譜面遷移

一次性工具：scripts/migrate-firebase-scores.mjs（npm run scores:firebase:migrate）。遷移流程為舊 V2/V3 -> legacy parser -> Canonical/Runtime events -> Slim 3.2 -> 新文件；保留舊原始資料，不直接覆蓋。預期欄位包含 migrationStatus、sourceFormat、storageFormat、version 與 migratedAt，並提供盤點/dry-run 與可重跑保護。腳本已建立，但尚未以正式 Firebase 憑證盤點或執行；不得宣稱舊譜面數量與自動轉換比例已確認。

## MusicXML / MXL 規則

- MXL 是壓縮包，解析前須展開 META-INF/container.xml 指定的主譜檔。
- 目前轉換器支援 score-partwise；score-timewise 會明確報錯。
- 多聲部、反覆記號與裝飾音等未支援資訊需在轉換品質摘要中揭露。
- 大型 MusicXML 不應直接存入 Firestore；先轉成 Slim 或存放 Storage。

## 除錯入口

- MIDI 解析與 track/program 問題：midiToSlim.js 與 tests/midi-slim-roundtrip.test.js。
- Tempo / PPQ / 拍號或 MIDI 匯出：scoreToMidi.js。
- Runtime 正規化與舊格式相容：score.js。
- Firebase 譜面遷移與欄位：scripts/migrate-firebase-scores.mjs、04_Firebase與雲端曲庫記憶.md。
- DAW 人工 SOP 與樣本說明：tests/fixtures/midi/README.md。
