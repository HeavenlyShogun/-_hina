# 譜面系統與轉換記憶

最後更新：2026-05-15

## 目前有效的譜面格式

### 編輯器主格式

- `version: "2.0"`
- 結構：
  - `meta`
  - `transport`
  - `playback`
  - `source`
  - `tracks[].events[]`

### 支援的輸入來源

- 文字譜
- JSON 譜
- MIDI
- MusicXML
- Slim Score `version: "3.2-ultra-slim"`

### 正規化入口

- `src/utils/score.js`
- 主要方法：`normalizeScoreSource()`
- 所有播放、預覽、合併、AI 轉換後載入，都應以這裡為準

## Slim Score 現況

- 前端主曲庫入口：`風物之琴譜/縮小版可匯入譜面/slim-json/*-slim.json`
- Slim Score 仍是重要來源格式，但不是編輯器直接維護格式。
- 一旦載入編輯器、合併、匯出或雲端存檔，主流程仍以 editor JSON v2 為核心。

## 編輯器匯出

位置：`src/components/SheetDisplay.jsx` + `src/App.jsx`

目前支援：

- JSON
- MIDI
- 原始譜面

規則：

- 若目前是 JSON 譜，下載 JSON 直接輸出目前內容。
- 若目前是文字譜，下載原始譜面輸出文字內容。
- 若下載 MIDI，會先把目前譜面整理成可輸出的 score JSON，再轉成 `.mid`。

## 轉換器目前行為

位置：`src/components/ScoreConverter.jsx`

### 已確定的 UI 結構

- 批次匯入按鈕
- 拖放 MusicXML 區
- Pending Uploads
- AI 輔助轉換

### 已移除的舊概念

- `Current Payload` 不再是轉換器主畫面。

### 手動草稿輸入

- `Source Draft` 是目前唯一保留的手動貼譜 / 貼 JSON / AI 草稿入口。

## 覆蓋與接到後面

### 覆蓋到譜面編輯

- 直接以新的 payload 取代目前 editor 內容。

### 接到後面

- 位置：`src/App.jsx`
- 主要邏輯：`mergeConvertedScorePayloads()`
- 規則：
  - 先把目前譜面與新譜面都用 `normalizeScoreSource()` 轉成 canonical event
  - 以目前譜面末尾 tick 作為偏移量
  - 將新譜面的事件整體後移
  - 再重建成 editor 可接受的 JSON v2 `tracks[].events[]`
- 用途：
  - 同一首歌切成多檔後依序合併
  - 不是字串拼接，而是時間軸合併

## AI 輔助轉換

位置：`src/utils/scoreConversionAssist.js`

### 目前要求

- JSON 輸出要符合目前 editor schema `version 2.0`
- 輸出必須可直接載入目前譜面編輯系統
- 以 `tracks[].events[]` 為主
- 使用整數 tick 與 `transport.resolution`
- 不再鼓勵使用舊 timed-token 思維

### 若未來改 schema

- 先改 `scoreConversionAssist.js`
- 再更新本檔
- 再檢查 `ScoreConverter.jsx`、`SheetDisplay.jsx`、`scoreToMidi.js`、`useScorePlayback.js`
