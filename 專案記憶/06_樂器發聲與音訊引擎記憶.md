## 樂器分類

- `sampled`：使用 SoundFont、WAV、MP3 或 AudioBuffer。
- `synthesized`：使用 Web Audio oscillator、filter、ADSR、vibrato、harmonics 等合成參數。
- 2026-06-03 起樂器選擇收斂為單一 tone id；若舊狀態傳入 tone array，`normalizeToneSelection()` 只保留第一個合法 tone。

## 發聲流程

1. UI 或播放排程要求 tone。
2. `useScorePlayback` 先 resume AudioContext，再呼叫 `prepareTone()` 或直接發 live note。
3. `audioEngine` 依 `AVAILABLE_INSTRUMENTS` 判斷 sample 或 synthesized。
4. sample 類先嘗試載入 MIDI.js / FluidR3 GM、tonejs-instruments、Oramics drums 或 sampleSet；失敗時 fallback 到合成 preset。
5. note 進入 dry output 與 reverb bus，再經 compressor/master output 到 destination。

## 目前音色方向

- MIDI 原始音色：尊重匯入譜面的 program/channel。
- Piano 類：適合主旋律、基準音準與轉檔檢查。
- Guitar / tongue drum / synth 類：適合角色化音色與 UI 展示。
- 合成音色需提供可離線 fallback，避免 CDN sample 載入失敗時完全無聲。
- 目前 SoundFont 來源：`https://gleitz.github.io/midi-js-soundfonts/FluidR3_GM/`。
- 目前原聲 sample 來源：
  - Piano / Guitar / Harp / Flute：`https://nbrosowsky.github.io/tonejs-instruments/samples/`
  - Drums：`https://oramics.github.io/sampled/DRUMS/pearl-master-studio/samples/`
- SoundFont 載入 timeout 目前為 `6000 ms`，單一 sample 載入 timeout 為 `8000 ms`。
- `Tone.Sampler` 載入 timeout 目前為 `8000 ms`；若 onload/onerror 沒有回來，會 reject 並走合成 fallback，避免播放卡在「載入音色與譜面中...」。
- live note 已調整成先發聲、背景預載 tone；避免首次按鍵被 sample 載入等待拖慢。
- 電子合成主音 `tongue-drum-electronic`、`retro-saw-synth`、`cozy-triangle-lead` 明確使用 `Tone.PolySynth`。
- 播放中會鎖定 `InstrumentSelector` 的樂器按鈕與 Blend toggle，避免排程期間更換 tone 造成音訊狀態不一致。

## 節拍器

- 作業位置：`src/components/ControlPanel.jsx`。
- 節拍器使用獨立 Web Audio click，不依賴譜面播放排程，也不改動 `playbackController` 的 tick-based transport。
- 速率範圍為 30.0 到 240.0 BPM。
- 第一拍依目前拍號分子做較高頻重音，其餘拍使用一般 click。
- 清理時需同時釋放 metronome timer 與 AudioContext 相關資源。

## 音訊品質檢查

- 首次播放需處理 AudioContext resume。
- 同一時間大量 note 需避免爆音與過高增益。
- 排程應以 tick、tempo map、secondsPerTick 為準，不直接依賴 UI frame。
- live note 與 scheduled note 應使用同一套音高轉換規則。
- reverb、release、filter 變更後需檢查尾音是否截斷。
- master output 與 compressor 已降低預設增益，避免多音同時播放爆音；若音量不足，先調 tone preset 或 outputGain，不要直接移除 compressor。
- 播放排程會將同一 tick 的 `simultaneousNotes` 傳入 `scheduleNote()`，再由 `denseGainScale = 1 / sqrt(simultaneousNotes)` 降低密集音符增益；底限為 `DENSE_NOTE_GAIN_FLOOR = 0.16`。
- release 需同時處理 envelope/noise/hammer gain，避免 piano 類音色尾音殘留或 click。

## 除錯入口

- 無聲：檢查 AudioContext、sample 載入、`prepareTone()`、使用者互動解鎖。
- 音高錯：檢查 MIDI note/frequency、global key offset、scale mode、accidentals。
- 節奏錯：檢查 `playbackController.js` tempo map 與 `useScorePlayback.js`。
- 音色錯：檢查 `AVAILABLE_INSTRUMENTS`、音色 id、sampleSet、fallback preset。
- 首次按鍵延遲：檢查 sample CDN、`fetchWithTimeout()`、`prepareTone()` 是否被 await 在互動路徑上。
- 播放卡在載入中：檢查 `loadToneSampler()` 的 timeout、Tone.Sampler onload/onerror、sample CDN 與 fallback log。
- 播放中爆音：檢查 `DEFAULT_RENDER_CONFIG.outputGain`、velocity、reverbAmount、compressor 設定與同時發聲數。
- 樂器切換錯誤：檢查 `normalizeToneSelection()` 是否仍收到舊 tone array、`InstrumentSelector.jsx` 是否維持單選、`AVAILABLE_INSTRUMENTS` id 是否一致。
- 節拍器無聲或殘留：檢查 `ControlPanel.jsx` 的 Web Audio click、timer 清理與 unmount cleanup。

## ESP32 Hina Lyre 硬體音訊韌體（2026-09-23）

- 韌體來源：`外接硬體資訊/hina_lyre_main.ino`。目標 ESP32 30-pin ESP-WROOM-32 + VS1053B，並使用共用 SPI MicroSD。
- 21 鍵對應 MIDI 48–83 範圍內的 21 個自然音，Channel 0、Program 0 Acoustic Grand Piano；VS1053B 使用官方 VLSI RT-MIDI 1.2 patch。
- MicroSD `/song.txt` 格式為 `note,duration_ms,gap_ms`，單音事件逐行讀取；播放鍵觸發一次性播放，暫停鍵或琴鍵中斷會送 CC 123。
- 矩陣為 4x6：掃描輸出 GPIO13/14/25/26，讀取輸入 GPIO27/32/33/34/35/36；GPIO34/35/36 僅輸入，需外接 10 kΩ 上拉。建議每鍵加隔離二極體以避免矩陣鬼鍵。
- 韌體已寫入但尚未上板編譯或實測。硬體音訊行為與網站 `src/services/audioEngine.js` 分屬兩個執行環境；本韌體不依賴瀏覽器音色資源。
