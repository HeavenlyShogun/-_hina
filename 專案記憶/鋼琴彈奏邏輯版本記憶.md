## 3 版：Tick 動態事件清單邏輯

第 3 版已定義為以 Tick 為基準的動態事件模型。它不把音符放進格子，也不以 note-duration 物件作為最終播放資料，而是把所有輸入解析成按時間排序的事件清單。

| 項目 | 內容 |
|---|---|
| 名稱 | Tick 動態事件清單邏輯 |
| 解決問題 | 靜態格子、跨格音符、切分音、三連音、和弦並行與休止符資料污染 |
| 與 2 版差異 | 2 版主資料是 `startTick + durationTicks` 的 canonical note；3 版主資料是 `(tick, note, action)` 事件 |
| 資料格式 | JSON `version: "3.0"`；事件欄位包含 `tick`、`type`、`note`、`velocity`、`trackId` |
| parser 規則 | 任何輸入都必須轉成整數 tick 事件；不輸出 rest event；不使用 float 作主時間軸 |
| 播放器規則 | 掃描事件清單，遇到 `note_on` 按下，遇到 `note_off` 放開 |
| 相容策略 | 2 版 note 可轉成 3 版：一筆 note 展開成一個 `note_on` 與一個 `note_off` |

## 長期記憶規則

- 說「1 版」時，指舊版鍵位譜 slash cell 邏輯。
- 說「2 版」時，指新版 canonical event / 簡譜時值邏輯。
- 說「3 版」時，指 Tick 動態事件清單邏輯。
- 目前實作仍可維持 2 版過渡；新增下一代 parser、播放器、MIDI 匯出與練習判定時，應以 3 版事件模型為目標。
- 只有匯入舊譜或修相容性時才回到 1 版。
- 不論來源格式為何，3 版目標是最終轉成 `(tick, note, action)` 事件清單。
