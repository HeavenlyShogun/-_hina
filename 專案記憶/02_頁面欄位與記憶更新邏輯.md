# 頁面欄位與記憶更新邏輯

最後更新：2026-06-05

本檔記錄 UI 區塊、狀態來源與哪些改動要回寫到哪份記憶。目的不是替代程式碼，而是讓後續作業能快速找到正確入口。

## 主頁與工作區

- 作業位置：`src/pages/PianoRoom.jsx`、`src/components/PianoKeys.jsx`、`src/components/SheetDisplay.jsx`
- 主要內容：特色曲目、曲目群組、忙碌狀態、工作區切換、播放預覽。
- 導覽來源：`src/App.jsx` 的 `workspaceSections`，需與畫面上的 section id 保持一致。
- 異動檢查：新增或移除工作區時，同步檢查 `AppHeader`、首頁快捷入口與 scroll target。
- 相關記憶：系統結構寫入 `01`，美術與介面寫入 `07`。

## 琴鍵與演奏控制

- 作業位置：`src/components/PianoKeys.jsx`
- 狀態來源：`activeKeys`、`keyPulseTokens`、`noteTrail`、`playHotkey`、`accidentals`。
- 發聲來源：live note 透過 `useScorePlayback` 呼叫 `audioEngine.playLiveNote()`，需與排程播放使用同一套音高規則。
- 異動檢查：改鍵位、升降記號或視覺 pulse 時，確認實際 frequency 與畫面 active key 不分裂。
- 相關記憶：琴鍵互動與視覺回饋寫入 `07`；按鍵對音高、播放排程、音訊問題寫入 `06`。

## 節奏與音訊控制

- 作業位置：`src/components/ControlPanel.jsx`、`src/contexts/AudioConfigContext.jsx`
- 主要欄位：`bpm`、`timeSigNum`、`timeSigDen`、`charResolution`、`tone`、`reverb`、`globalKeyOffset`、`scaleMode`、`accidentals`。
- 狀態落點：節奏/調性會影響 score normalization；tone/reverb 會影響 `audioEngine` render config。
- 異動檢查：控制面板預設值需與 `src/constants/music.js` 的 `DEFAULT_SCORE_PARAMS` 一致或有明確覆寫理由。
- 節拍器：`ControlPanel` 內的 metronome 使用獨立 Web Audio click，速率範圍 30.0 到 240.0 BPM，依拍號分子做第一拍重音，不走 `playbackController`。
- BPM 更新：主 BPM 套用以 `requestAnimationFrame` 節流；修改時要確認 unmount 會取消尚未執行的 animation frame。
- 相關記憶：樂器與發聲寫入 `06`；譜面參數如何落到 schema 寫入 `03`。

## 譜面顯示與編輯

- 作業位置：`src/components/SheetDisplay.jsx`、`src/components/ScoreEditor.jsx`
- 主要欄位：曲名、來源格式、JSON 內容、MIDI 匯出、MusicXML 匯入、儲存、重設、唯讀狀態。
- 資料責任：UI 只負責顯示與提交，格式修正要放在 `scoreDocument.js` 或對應 converter 工具。
- 異動檢查：下載 JSON/MIDI/原始譜面後，至少確認可重新匯入或能被 `normalizeScoreSource()` 接受。
- 相關記憶：schema 與轉檔寫入 `03`；雲端儲存寫入 `04`；UI 行為寫入 `07`。

## 轉檔器

- 作業位置：`src/components/ScoreConverter.jsx`
- 主要能力：MIDI 轉 JSON、MusicXML/MXL 轉 Slim JSON、批次待上傳、格式檢查、AI 輔助轉換、Source Draft。
- 佇列責任：Pending Uploads 只保存轉換後候選，不應繞過大小檢查直接寫 Firestore。
- 異動檢查：覆蓋、接到後面、批次上傳三條路徑都需共用 canonical payload。
- 相關記憶：格式與轉換規則寫入 `03`；上傳流程寫入 `04`。

## 雲端曲庫

- 作業位置：`src/components/ScoreLibrary.jsx`、`src/hooks/useCloudScores.js`
- 主要能力：連線狀態、儲存、載入、刪除、錯誤訊息。
- 狀態來源：`cloudStatus`、`cloudError`、`savedScores`、目前 Firebase context。
- 異動檢查：任何列表摘要欄位變更，都要確認完整文件與 summary 文件仍可互相對應。
- 相關記憶：Firebase/Auth/Firestore 寫入 `04`；部署與環境差異寫入 `05`。

## 樂器選擇

- 作業位置：`src/components/InstrumentSelector.jsx`、`src/pages/PianoRoom.jsx`
- 狀態來源：`tone`、`isBusy`、`isPlaybackActive`。
- 播放中規則：`App.jsx` 以目前 `isPlaying` 傳入 `PianoRoom`，播放中會鎖定樂器按鈕與 Blend toggle。
- 異動檢查：任何可在播放中改 tone 的入口，都要確認不會繞過 disabled 狀態。
- 相關記憶：音色行為寫入 `06`；disabled 視覺狀態寫入 `07`。

## 記憶更新規則

- 介面或版面變更：更新 `07`，若牽涉狀態欄位也更新本檔。
- 樂譜格式、轉檔、匯入匯出：更新 `03`。
- 樂器、音色、播放延遲、聲音品質：更新 `06`。
- Firebase 設定、資料結構、雲端錯誤：更新 `04`。
- GitHub Pages、Firebase Hosting、build scripts：更新 `05`。
