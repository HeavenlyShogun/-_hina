# 第三版：Tick 動態事件清單邏輯

更新日期：2026-05-09

本檔記錄 Project Hina 第三版鋼琴／風物之琴彈奏邏輯。說「第三版」、「3 版」或「Tick 動態事件邏輯」時，指本檔定義。

## 狀態

已定義，作為下一代主線規格。第二版仍可作為相容與過渡層；第三版是新的目標資料模型。

## 核心定位

第三版捨棄靜態格子與 note-duration 主資料，改用以 Tick 為基準的動態事件清單。音樂不再被塞進小節格、拍格或四格中，而是被表示為一連串按照時間排序的事件。

每一個可發聲音符由兩個事件組成：

- `note_on`：按下音符。
- `note_off`：放開音符。

核心元組為：

```txt
(tick, note, action)
```

實際資料可擴充為：

```json
{
  "tick": 0,
  "type": "note_on",
  "note": "C4",
  "velocity": 64,
  "trackId": "right"
}
```

## 對應格式與參數

| 項目 | 定義 |
|---|---|
| JSON score | JSON `version: "3.0"` |
| time model | absolute timeline |
| event model | `(tick, note, action)` |
| action | `note_on`、`note_off`、`control_change` |
| resolution | `TPB = 480` |
| measure model | 小節只是 tick 範圍，不是資料容器 |

## 規則

| 規則 | 記憶定義 |
|---|---|
| 時間基準 | `TPB = 480`，一拍等於 480 ticks。 |
| 小節長度 | 4/4 一小節為 `4 * 480 = 1920` ticks。 |
| 事件排序 | 所有事件依 `tick` 升冪排序；同一 tick 可有多個事件。 |
| 音符表示 | 音符不保存為單一 duration 物件，而是保存為 `note_on` 與 `note_off` 事件。 |
| 多音並行 | 和弦是多個同 tick 的 `note_on`；結束時是多個同 tick 的 `note_off`。 |
| 左右手 | 左手、右手或多聲部用不同 `trackId` 或不同 track list 保存。 |
| 休止符 | 休止符不作為事件存在，只是兩個發聲事件之間的 tick 空白。 |
| 秒數 | 秒數只由 tempo 與 tick 推導，不可作為主時間軸。 |

## 為什麼不用格子

靜態四格模型會強迫 4/4 拍的小節被切成四個框。當音符從第一拍後半開始、延續到第二拍後半，或音符長度是 `1.5` 拍時，它會跨越格線。若硬切，音樂連貫性會被破壞；若不切，資料結構會變得臃腫且難以解析。

第三版只看絕對 tick：

- 音符開始：一個 `note_on` 事件。
- 音符結束：一個 `note_off` 事件。
- 音符長度：`note_off.tick - note_on.tick`。

小節只負責定位。例如 4/4、`TPB = 480`：

```txt
measure 1 = [0, 1920)
measure 2 = [1920, 3840)
```

只要事件的 `tick` 落在該範圍內，它就屬於該小節。事件可以跨小節，不需要被切開。

## Tick 與三連音

第三版禁止用 float 拍數或秒數累加作為主時間軸。使用 `TPB = 480` 的原因是它可以整除常見二分與三分節奏：

| 音值 | ticks |
|---|---:|
| 四分音符 | 480 |
| 八分音符 | 240 |
| 十六分音符 | 120 |
| 三連音一個音 | 160 |

這樣三連音不需要 `0.3333...` 拍，也不會在多小節後累積出左右手 desync。

## 多音並行

和弦不需要特殊容器。右手同時彈 C 大三和弦時，三個音的 `note_on` 共用同一個 tick：

```js
const timelineEvents = [
  { tick: 0, type: "note_on", note: "C4", velocity: 64, trackId: "right" },
  { tick: 0, type: "note_on", note: "E4", velocity: 64, trackId: "right" },
  { tick: 0, type: "note_on", note: "G4", velocity: 64, trackId: "right" },
  { tick: 480, type: "note_off", note: "C4", trackId: "right" },
  { tick: 480, type: "note_off", note: "E4", trackId: "right" },
  { tick: 480, type: "note_off", note: "G4", trackId: "right" },
  { tick: 480, type: "note_on", note: "D4", velocity: 80, trackId: "right" }
];
```

播放時只要掃描目前 tick 對應的事件：

```txt
if current_tick == event.tick:
  execute(event.action, event.note, event.velocity)
```

## 左右手與 Track

第三版可以用兩種等價方式保存左右手：

```js
const trackLeft = [
  { tick: 0, type: "note_on", note: "C3", velocity: 64 },
  { tick: 480, type: "note_off", note: "C3" }
];

const trackRight = [
  { tick: 0, type: "note_on", note: "C4", velocity: 64 },
  { tick: 0, type: "note_on", note: "E4", velocity: 64 },
  { tick: 480, type: "note_off", note: "C4" },
  { tick: 480, type: "note_off", note: "E4" }
];
```

或合併成單一 timeline，並用 `trackId` 區分：

```js
[
  { tick: 0, type: "note_on", note: "C3", velocity: 64, trackId: "left" },
  { tick: 0, type: "note_on", note: "C4", velocity: 64, trackId: "right" },
  { tick: 0, type: "note_on", note: "E4", velocity: 64, trackId: "right" }
]
```

## 分析規則

音符長度由事件配對計算：

```txt
durationTicks = note_off.tick - note_on.tick
```

例：

- `120` ticks：十六分音符。
- `160` ticks：三連音中的一個音。
- `720` ticks：附點四分音符。

休止符由空白區間推導：

```txt
restTicks = next_note_on.tick - previous_note_off.tick
```

若 `restTicks > 0`，該區間就是休止；不需要建立 rest event。

## Parser 規則

第三版 parser 的任務是把任何輸入格式轉成事件清單：

```txt
input text -> parse tokens -> resolve pitch/rhythm -> emit (tick, note, action)
```

輸出必須符合：

- 所有 `tick` 都是整數。
- 所有音符都有 `note_on` 與 `note_off`。
- 不輸出休止符事件。
- 不輸出 float 拍數作為主時間。
- 不依賴固定格子保存節奏。
- 同 tick 多事件必須被保留，用來表示和弦與左右手同步。

## 與第二版差異

| 項目 | 第二版 | 第三版 |
|---|---|---|
| 主資料 | canonical note，含 `startTick` 與 `durationTicks` | dynamic event，含 `tick`、`note`、`action` |
| 音符表示 | 一筆 note 代表開始與長度 | `note_on` + `note_off` 兩筆事件 |
| 休止符 | 不進 canonical 主資料 | 不存在，只由事件空白推導 |
| 和弦 | 多筆 note 共用 `startTick` | 多筆 `note_on` 共用 `tick` |
| 播放器 | 可先展開為事件流 | 直接讀事件流 |
| 分析長度 | `durationTicks` | `note_off.tick - note_on.tick` |

## 使用原則

- 說「第三版」時，指本檔的 Tick 動態事件清單邏輯。
- 第三版的主資料是事件清單，不是格子、不是拍數、也不是 note-duration 物件。
- 新增下一代 parser、播放器、MIDI 匯出與練習判定時，應以第三版事件模型為目標。
- 第二版資料可以轉成第三版：每筆 note 產生一個 `note_on` 與一個 `note_off`。
